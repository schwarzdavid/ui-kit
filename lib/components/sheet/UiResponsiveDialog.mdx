# UiResponsiveDialog and UiBottomSheet

`UiResponsiveDialog` is the shell of every dialog preset of this library. Above Vuetify's `mobileBreakpoint` it renders a centred dialog, below it a bottom sheet. `UiBottomSheet` is that sheet on its own, for UIs that should be a sheet on every screen size. Both are exported from `@schwarzdavid/ui-kit` and need the plugin to be installed.

The built-in `info()`, `confirm()` and `form()` presets already render through `UiResponsiveDialog`, so you only use it directly in your own [custom presets](?path=/docs/custom-presets--docs) or in templates that manage their own `v-model`.

The stories below start with a phone viewport. Storybook only applies a viewport to the canvas, so open a story in its own tab (not inside this docs page) or resize the window below the breakpoint to see the sheet.

## Stages

A sheet has up to three stages:

<table>
    <thead>
    <tr>
        <th>Stage</th>
        <th>Shows</th>
        <th>Height</th>
    </tr>
    </thead>
    <tbody>
    <tr>
        <td>`preview`</td>
        <td>Handle, title and the `preview` slot. Only exists when the `preview` slot is filled.</td>
        <td>As tall as its content</td>
    </tr>
    <tr>
        <td>`content`</td>
        <td>The default slot instead of the preview, with a close button in the header</td>
        <td>As tall as its content, at most `90dvh`</td>
    </tr>
    <tr>
        <td>`fullscreen`</td>
        <td>The default slot with a close button in the header. Only exists when `expandable` is `true`.</td>
        <td>`100dvh`</td>
    </tr>
    </tbody>
</table>

The sheet opens in the first available stage, or in `stage` when it is one of them. The user changes the stage by dragging the handle or the header up or down, or by activating the handle (a button labelled with the `expand` or `collapse` message, depending on the stage). Dragging down from the lowest stage dismisses the sheet and emits `update:modelValue` with `false` and `close`, so `v-model` closes it; a parent that only binds `:model-value` decides itself whether to close. While `persistent` is set the sheet springs back instead. A downward drag inside a scrolled body scrolls the content first, and a mostly horizontal gesture never drags the sheet.

The body of a stage scrolls while the `actions` stay visible below it.

## UiResponsiveDialog

<Story of={ResponsiveDialogStories.Default} />

The demo uses the `preview` slot for a summary line, the default slot for the fields and the `actions` slot for Save and Cancel.

```vue
<UiResponsiveDialog v-model="open" v-model:stage="stage" title="Edit profile" form @submit="save">
    <template #preview>
        <p>{{ summary }}</p>
    </template>
    <VTextField v-model="name" label="Name" />
    <VTextField v-model="email" label="Email address" type="email" />
    <template #actions>
        <VBtn variant="text" @click="open = false">Cancel</VBtn>
        <VBtn variant="flat" color="primary" type="submit">Save</VBtn>
    </template>
</UiResponsiveDialog>
```

### Menus and short content

Set `expandable` to `false` for content that never needs more room. Without a `preview` slot the sheet then has a single stage and cannot be dragged up; it can still be dismissed by swiping down.

<Story of={ResponsiveMenuStories.Default} />

```vue
<UiResponsiveDialog v-model="open" title="Message actions" width="sm" :expandable="false">
    <VList :items="items" item-title="title" item-value="id" @click:select="choose" />
</UiResponsiveDialog>
```

## UiBottomSheet

`UiBottomSheet` takes the same props (except `width`), slots and events. Its `title` is optional. Use it when the sheet should stay a sheet on desktop too. Its body has no horizontal padding, so lists and dividers reach the edges of the sheet; wrap text and form fields in a `VCardText` or add your own padding. `UiResponsiveDialog` keeps the padding on mobile. The demo shows the current `v-model:stage`.

<Story of={BottomSheetStories.Default} />

```vue
<UiBottomSheet v-model="open" v-model:stage="stage" title="Filters">
    <template #preview>
        <VCardText class="py-0">{{ filters.length }} filters active</VCardText>
    </template>
    <VList v-model:selected="filters" select-strategy="leaf" lines="one">
        <VListItem v-for="filter in options" :key="filter.value" :value="filter.value" :title="filter.title">
            <template #append="{ isSelected }">
                <VCheckboxBtn :model-value="isSelected" tabindex="-1" />
            </template>
        </VListItem>
    </VList>
    <template #actions>
        <VBtn variant="flat" color="primary" @click="open = false">Apply</VBtn>
    </template>
</UiBottomSheet>
```

## Things to know

- The switch follows Vuetify's `display.mobileBreakpoint` through `useDisplay().mobile`. The shipped [Vuetify configuration](?path=/docs/vuetify-theme--docs) sets it to `'sm'`; without it Vuetify's default applies.
- Content in the `header` slot gets `touch-action: none` on mobile, because the header is a drag area. Horizontal scrolling there does not pan.
- Crossing the breakpoint while the dialog is open (rotating a phone, resizing a window) swaps the presentation without closing it. The default slot stays mounted and is moved into the new layout, so its local state survives, including content registered through `useDialogForm` in the Form preset. The `preview`, `header` and `actions` slots are rendered again, so keep their state in the parent. A focused field in the default slot loses focus when it is moved. `opened` fires again once the new presentation has entered; the Form preset uses it to focus its first field again.
- The default slot is mounted when the dialog opens and unmounted after `closed`, so it starts fresh every time the dialog opens again.
- On some phones the on-screen keyboard may cover the actions. This is not handled yet.
- The labels of the handle and the close icon come from the `expand`, `collapse` and `close` [i18n messages](?path=/docs/configuration--docs).
