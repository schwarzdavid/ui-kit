# useDialog

Open dialogs from script instead of declaring them in templates. Every method pushes a dialog into a queue and returns a Promise that settles when the dialog closes, so the calling code reads top to bottom:

```ts
const dialog = useDialog()

if (await dialog.confirm('items.delete.title', 'items.delete.content', ConfirmDialogLevel.DANGER)) {
    await api.deleteItem(id)
}
```

The dialogs are rendered by `UiKitOutlet`; see [Installation](?path=/docs/installation--docs) for registering the plugin and placing the outlet.

Each method is rendered by a preset component that you can [replace](#replacing-the-dialog-components) with your own.

## Layout and behaviour

Every dialog shares one shell: a title, a scrolling body and a footer with the buttons in the order tertiary, then primary. Three widths exist, `sm` (440px), `md` (560px) and `lg` (720px); every method accepts a `width` option of type `DialogWidth` (`'sm' | 'md' | 'lg' | number`). Form dialogs go full screen below Vuetify's `sm` breakpoint. Escape and a click on the overlay behave like the cancel button; set the plugin option `dialog.closeOnOverlayClick` to `false` to keep dialogs open on overlay clicks (see [Configuration](?path=/docs/configuration--docs)).

All queued dialogs are rendered at once, the newest on top. A dialog can therefore open another one, e.g. a confirm from an `additionalCta` action of an info dialog or from the `action` of a form dialog, and the first one stays open underneath until it is closed itself.

## DialogComposable::info()

Info dialogs are only meant to show information to the user or to ask for very simple choices (e.g. override/create new profile). However, **do not** use this function to ask for user confirmation, e.g. to ask the user for confirmation before deleting an entity. The `DialogComposable::confirm` is better suited for these kinds of requirement.

### Example implementation

`InfoDialogContent` in this example declares `defineProps<{ foo: number }>()`, so `props` must be passed.

```vue
<template>
    <div class="d-flex gc-4">
        <VBtn variant="flat" color="primary" @click="openTextDialog">Text content</VBtn>
        <VBtn @click="openComponentDialog">Component content</VBtn>
        <VBtn @click="openAdditionalCtaDialog">Additional actions</VBtn>
        <VBtn @click="openChoiceCtaDialog">Simple Choice</VBtn>
    </div>
    <p v-if="actionCount" class="mt-4">Action triggered {{ actionCount }} times</p>
    <p v-if="pill" class="mt-4">You chose: {{ pill }}</p>
</template>

<script lang="ts" setup>
    import { ref } from 'vue'
    import { useDialog } from '@schwarzdavid/ui-kit'
    import InfoDialogContent from './InfoDialogContent.vue'

    const dialog = useDialog()
    const pill = ref<string | null>(null)
    const actionCount = ref(0)

    function openTextDialog(): void {
        void dialog.info('Text Dialog', 'Lorem ipsum...')
    }

    function openComponentDialog(): void {
        void dialog.info({
            title: 'Component Dialog',
            component: InfoDialogContent,
            props: {
                foo: 5,
            },
        })
    }

    function openAdditionalCtaDialog(): void {
        void dialog.info({
            title: 'Additional Actions',
            content: 'Lorem ipsum...',
            additionalCta: [
                {
                    text: 'Trigger action',
                    translateText: false,
                    action: () => { actionCount.value++ },
                },
            ],
        })
    }

    async function openChoiceCtaDialog(): Promise<void> {
        pill.value = await dialog.info<string>({
            title: 'Choice Cta',
            content: 'You take the blue pill ... the story ends. You take the red pill ... you stay in wonderland',
            defaultCta: false,
            additionalCta: [
                {
                    text: 'Red pill',
                    translateText: false,
                    value: 'Red Pill',
                },
                {
                    text: 'Blue pill',
                    translateText: false,
                    value: 'Blue Pill',
                },
            ],
        })
    }
</script>
```

## DialogComposable::confirm()

The confirm method is used to ask for user confirmation. It comes with different confirmation levels (default, warning, danger) and always resolves to `true`/`false`. When you need other options, e.g. a number, string or a nullable boolean, use the `DialogComposable::info()`-function.

### Example implementation

```vue
<template>
    <div class="d-flex gc-4">
        <VBtn variant="flat" color="primary" @click="openDefaultConfirmDialog">Default Confirm choice</VBtn>
        <VBtn @click="openWarningConfirmDialog">Warning choice</VBtn>
        <VBtn @click="openDangerousConfirmDialog">Dangerous choice</VBtn>
        <VBtn @click="openCustomConfirmDialog">Custom content</VBtn>
    </div>

<script lang="ts" setup>
    import { ref } from 'vue'
    import { useDialog, ConfirmDialogLevel } from '@schwarzdavid/ui-kit'
    import ConfirmDialogContent from './ConfirmDialogContent.vue'

    const dialog = useDialog()
    const lastChoice = ref<boolean | null>(null)

    async function openDefaultConfirmDialog(): Promise<void> {
        lastChoice.value = await dialog.confirm('items.delete.title', 'items.delete.content')
    }

    async function openWarningConfirmDialog(): Promise<void> {
        lastChoice.value = await dialog.confirm('items.warning.title', 'items.warning.content', ConfirmDialogLevel.WARNING)
    }

    async function openDangerousConfirmDialog(): Promise<void> {
        lastChoice.value = await dialog.confirm({
            title: 'Attention!',
            translateTitle: false,
            content: 'Are you sure to delete this item?',
            translateContent: false,
            level: ConfirmDialogLevel.DANGER,
            permanent: true,
        })
    }

    async function openCustomConfirmDialog(): Promise<void> {
        lastChoice.value = await dialog.confirm({
            title: 'Custom component',
            translateTitle: false,
            component: ConfirmDialogContent,
            confirmCta: {
                text: 'Confirm',
                translateText: false,
            },
            rejectCta: {
                text: 'Abort',
                translateText: false,
            },
        })
    }
</script>
```

## DialogComposable::form()

Form dialogs render a component of your own inside a dialog with a cancel and a save button and resolve with the value it produces. This covers everything from a single input (rename a field, pick a folder) to a validated form or a complex picker with its own filters. The dialog validates with Vuelidate and optionally runs an asynchronous action (e.g. an API call) before closing.

### Demo
<Story of={FormDialogStories.Default} />

### Usage

`dialog.form<T, R = T, Required extends boolean = false>(options: FormDialogProps<T, R, Required>): Promise<Required extends true ? R : R | null>`

`T` is the value your component produces and `R` is the value the Promise resolves with. Without an `action`, `R` equals `T`. `T` is inferred from `initialValue` or the parameter of `action`; otherwise pass it explicitly.

### How your component hands over its value

The dialog owns the frame, the buttons and the Promise; your component owns the content. There are two ways for the component to tell the dialog what to resolve with, and they can be combined:

    <thead>
    <tr>
        <th></th>
        <th>v-model</th>

    </tr>
    </thead>
    <tbody>
    <tr>
        <td>In your component</td>
        <td>`const model = defineModel<T>()`</td>
        <td>`useDialogForm(() => buildValue())`</td>
    </tr>
    <tr>
        <td>Start value</td>
        <td>`initialValue` arrives as `modelValue`</td>
        <td>Your component sets up its own state (pass data through `props`)</td>
    </tr>
    <tr>
        <td>Resolves with</td>
        <td>The model value at the moment of saving</td>
        <td>Whatever `finish()` returns; it may be async and may throw</td>
    </tr>
    <tr>
        <td>Extras</td>
        <td>`required: true` disables save while the value is empty</td>

When a component does both, `finish()` wins. That is the way to use a model for the start value and still call `submit()`, as the [folder picker](#picker-that-submits-on-double-click) does.

**What happens on save**

The save button, Enter in any field (the body is a `<form>`) and `submit()` all start the same sequence:

1. `useVuelidate().$validate()` runs and collects every Vuelidate instance created inside your component. If anything is invalid, the dialog stays open and your fields show their errors.
2. The value is taken from `finish()`, or from the model when no `finish` is registered.
3. `action(value)` runs if provided; the dialog resolves with its result, otherwise with the value.

While steps 2 and 3 run, the save button shows its loading state, cancel and the close icon are disabled and Escape is ignored. The busy state lasts at least `loading.delay` milliseconds of the plugin options. If `finish()` or `action` throws, the dialog stays open and shows an error alert at the top of the body with the `saveFailed` message as title and the error's message as text (or the `unknownError` message when the thrown value carries none); the user's input is kept.

**What happens on close**

Cancel, the close icon and Escape resolve the Promise with `null`. With `required: true` they reject instead, so the awaited value is never `null`; the dialog also rejects when the saved result is `null`.

### Examples

#### Single field

A single input only needs a model. The value type is inferred from `initialValue`, and with `required: true` the Promise resolves with a `string`, never `null`. Try "Rename" in the demo at the top of this section.

```vue
<template>
    <VTextField v-model="model" :label="label" />
</template>

<script lang="ts" setup>
    defineProps<{
        label: string
    }>()

    const model = defineModel<string | null>({ required: true })
</script>
```

```ts
const name = await dialog.form({
    title: 'Rename inbound form',
    component: FormDialogFieldContent,
    props: { label: 'Name' },
    initialValue: 'Contact request',
    required: true,
})
```

#### Required list

`required` treats empty arrays, empty objects, empty `Map`/`Set` and invalid dates as empty too, so save stays disabled until at least one label is chosen. Because cancelling rejects, wrap the call in `try/catch`.

<Story of={FormDialogTagsStories.Default} />

```vue
<template>
    <VCombobox v-model="model" :items="suggestions" label="Labels" multiple chips closable-chips />
</template>

<script lang="ts" setup>
    defineProps<{
        suggestions: string[]
    }>()

    const model = defineModel<string[] | null>({ required: true })
</script>
```

```ts
try {
    labels.value = await dialog.form({
        title: 'Edit labels',
        component: FormDialogTagsContent,
        props: { suggestions: ['customer', 'urgent', 'invoice'] },
        initialValue: [...labels.value],
        required: true,
    })
} catch {
    return
}
```

#### Picker that submits on double-click

The model brings the start value in, `useDialogForm` adds `submit()` and a Vuelidate rule blocks saving without a selection. Since `finish` is registered, it decides the result.

<Story of={FormDialogMoveStories.Default} />

```vue
<template>
    <VList v-model:selected="selected" :items="folders" item-title="name" item-value="id" mandatory @dblclick="submit" />
    <p v-if="v.model.$error" class="text-error">Choose a folder.</p>
</template>

<script lang="ts" setup>
    import { computed } from 'vue'
    import useVuelidate from '@vuelidate/core'
    import { useDialogForm } from '@schwarzdavid/ui-kit'
    import { required } from '@schwarzdavid/ui-kit/validators'

    defineProps<{
        folders: Folder[]
    }>()

    const model = defineModel<string | null>({ required: true })
    const selected = computed({
        get: () => model.value === null ? [] : [model.value],
        set: (value: string[]) => { model.value = value[0] ?? null },
    })
    const v = useVuelidate({ model: { required } }, { model })
    const { submit } = useDialogForm(() => model.value)
</script>
```

#### Validated form

A form with several fields keeps its own state and hands over the value through `finish`. Try "New profile" in the demo at the top of this section.

```vue
<template>
    <div class="d-flex flex-column ga-5">
        <VTextField v-model="v.name.$model" label="Name" :error="v.name.$error" />
        <VTextField v-model.number="v.age.$model" label="Age" type="number" :error="v.age.$error" />
        <VDateInput v-model="v.date.$model" label="Date" :error="v.date.$error" />
    </div>
</template>

<script lang="ts" setup>
    import { ref } from 'vue'
    import useVuelidate from '@vuelidate/core'
    import { useDialogForm } from '@schwarzdavid/ui-kit'
    import { maxLength, minLength, required } from '@schwarzdavid/ui-kit/validators'

    const state = ref<{ name: string, age: number | null, date: Date }>({
        name: '',
        age: null,
        date: new Date(),
    })

    const v = useVuelidate({
        name: { required, minLength: minLength(5), maxLength: maxLength(8) },
        age: { required },
        date: { required },
    }, state)

    useDialogForm(() => state.value.name)
</script>
```

```ts
const name = await dialog.form<string>({
    title: 'New profile',
    component: FormDialogContent,
})
```

#### Saving with an action

Pass an `action` to persist the value before the dialog closes. The Promise resolves with the action's result, so `T` (the form value) and `R` (the saved entity) differ. A thrown error stays inside the dialog and the user can correct the input; use an address containing "taken" to see it. The `loading` ref from `useDialogForm` disables the field while saving.

<Story of={FormDialogInviteStories.Default} />

```vue
<template>
    <VTextField v-model="v.email.$model" label="Email address" type="email" :error="v.email.$error" :disabled="loading" />
</template>

<script lang="ts" setup>
    import { ref } from 'vue'
    import useVuelidate from '@vuelidate/core'
    import { useDialogForm } from '@schwarzdavid/ui-kit'
    import { email, required } from '@schwarzdavid/ui-kit/validators'

    const state = ref({ email: '' })
    const v = useVuelidate({ email: { required, email } }, state)
    const { loading } = useDialogForm(() => state.value.email.trim())
</script>
```

```ts
const invitation = await dialog.form({
    title: 'Invite member',
    component: FormDialogInviteContent,
    action: (address: string) => api.sendInvitation(address),
})
```

## Replacing the dialog components

`info()`, `confirm()` and `form()` only queue an entry; what is rendered comes from the plugin options. Replace a preset when your application needs a different template, for example a bottom sheet instead of a centred dialog:

```ts
app.use(createUIKit({
    components: {
        dialog: {
            confirm: BottomSheetConfirm,
        },
    },
}))
```

The demo opens the same `dialog.confirm()` call once with the built-in preset and once inside a scope where `confirm` is replaced by a bottom sheet:

<Story of={DialogPresetsStories.Default} />

<table>
    <thead>
    <tr>
        <th>Option</th>
        <th>Renders</th>
        <th>`data` of `useDialogEntry()`</th>
        <th>Resolve with</th>
    </tr>
    </thead>
    <tbody>
    <tr>
        <td>`components.dialog.info`</td>
        <td>`dialog.info()`</td>
        <td>`InfoDialogProps<T>`</td>
        <td>`null` or the `value` of a custom button; the composable turns a reject into `null`</td>
    </tr>
    <tr>
        <td>`components.dialog.confirm`</td>
        <td>`dialog.confirm()`</td>
        <td>`ConfirmDialogProps`</td>
        <td>`true` / `false`; reject when `throwOnReject` is set and the user declines</td>
    </tr>
    <tr>
        <td>`components.dialog.form`</td>
        <td>`dialog.form()`</td>
        <td>`FormDialogProps<T, R, Required>`</td>
        <td>The value or the `action` result, `null` on close; reject when `required` is set and there is no result</td>
    </tr>
    </tbody>
</table>

A preset receives no props and emits nothing. It reads the caller's options through `useDialogEntry()`, renders them however it likes and settles the caller's Promise:

```vue
<template>
    <VBottomSheet :model-value="open" @update:model-value="() => close(false)" @after-leave="settle">
        <VSheet class="pa-6">
            <h2>{{ data.title }}</h2>
            <p v-if="'content' in data">{{ data.content }}</p>
            <VBtn variant="text" @click="() => close(false)">No</VBtn>
            <VBtn variant="flat" color="primary" @click="() => close(true)">Yes</VBtn>
        </VSheet>
    </VBottomSheet>
</template>

<script lang="ts" setup>
    import { ref } from 'vue'
    import { useDialogEntry, type ConfirmDialogProps } from '@schwarzdavid/ui-kit'

    const { data, resolve } = useDialogEntry<ConfirmDialogProps, boolean>()
    const open = ref(true)

    let confirmed = false

    function close(value: boolean): void {
        confirmed = value
        open.value = false
    }

    function settle(): void {
        resolve(confirmed)
    }
</script>
```

Things to keep in mind:

- A preset replaces the built-in one for the whole app; the keys you leave out keep their built-in presets. The callers do not change.
- Call `resolve` or `reject` after the leave transition, so the dialog animates out before it is removed from the queue.
- Honour the options your callers use, e.g. `translateTitle` (render user strings through vue-i18n), `width`, `permanent` or the CTA texts from `i18n.messages`.
- A custom form preset renders the caller's `component` with `data.props`. `useDialogForm()` only works inside the built-in form preset, so a replacement supports v-model components only.

See [Custom presets](?path=/docs/custom-presets--docs) for the complete `useDialogEntry()` contract and the toast counterpart.
